# 源视频章节 → 成片章节映射：工作流程说明

## 1. 任务与输入

- 源视频：`work/source.mp4`，60 秒、30fps、共 1800 帧，画面烧录了逐帧源时间码
  （`SOURCE TC ... FRAME nnnn`），便于对任意跳转位置做逐帧核对。
- 源章节：`work/source_chapters.json`，5 个章节，每个章节带
  中文（zh）、英文（en）、日文（ja）三种语言标题。
- 剪辑点列表：`work/cut_list.json`，4 个删除区间（C1–C4），时间故意包含
  非帧对齐的小数（如 8.42s、12.25s），用来验证“吸附到最近合法帧”。

## 2. 核心算法：为什么不是百分比缩放

映射完全由剪辑点列表逐帧构建，分四步（见 `scripts/map_chapters.py`）：

1. **帧吸附**：每个剪辑点起止秒数按“四舍五入（半帧向上）”吸附到最近合法帧，
   并记录吸附前后的 Δ 秒数。
2. **合并删除区间**：把可能相邻/重叠的删除帧区间合并，得到
   `removed_ranges_frames`。
3. **构建保留区间与旧→新帧映射表**：逐帧扫描 1800 个源帧，被删除的源帧记
   `None`，保留帧按顺序分配连续的新帧号。新时间只能通过这张映射表查到，
   不存在任何 `新时间 = 旧时间 × 成片时长/源时长` 的全局缩放。
4. **章节拆分/删除**：对每个源章节求其帧区间内的连续存活片段：
   - 无存活片段 → 整章删除；
   - 多个存活片段 → 章节拆分，标题加 `(P1)/(P2)`；
   - 存活片段短于 `min_kept_fragment_sec`（2.0s）→ 作为碎片删除并记录原因；
   - 章节边界落在删除区间内 → 边界吸附到最近的合法保留帧；
   - 片尾章节被整体删除时，最后一个存活章节延伸到成片结尾。

`scripts/verify_no_percentage_scaling.py` 用数据证明二者差异：纯百分比缩放
对章节 2/3/4 分别产生 21/45/15 帧的误差，而剪辑点映射逐帧精确。

## 3. 帧精确剪辑渲染

`scripts/render_edit.py` 依据 `work/edit_plan.json` 的保留帧区间，用
`trim=start_frame/end_frame`（视频）与 `atrim`（音频）裁剪，再经
`concat` 拼接，输出保持 30fps、PTS 从 0 严格帧对齐的中间片
`work/edited_no_chapters.mp4`（994 帧 = 33.133s）。

注意一个容器细节：AAC 的编码器 priming（1024 样本 ≈ 21ms）在 MP4 里由
edit-list 正确抵消，但重封装到 MKV 时会变成流偏移。因此 MKV 成片改用
FLAC 音轨（无 priming），保证视频 PTS 从 0 起始、章节时间精确。

## 4. 可重新导入的章节文件（`out/`）

- `edited_chapters_mkv.xml`：Matroska 章节 XML，保留 zh/en/ja 多语言标题，
  供 mkvmerge 导入：
  `mkvmerge -o out.mkv --chapters out/edited_chapters_mkv.xml work/edited_no_chapters.mp4`
- `edited_chapters_ffmetadata.txt`：FFmpeg ffmetadata 格式，MP4/MKV 均可重导入：
  `ffmpeg -i video.mp4 -i edited_chapters_ffmetadata.txt -map_metadata 1 -c copy out.mp4`
- `chapter_map.json`：机器可读的完整映射（旧/新时间、帧号、语言、状态、原因）。
- `chapter_mapping_report.md`：人工核对用的旧时间→新时间对照表与变更原因。
- `edited_with_chapters.mp4` / `edited_with_chapters.mkv`：已封装章节的成片。

MP4 容器的章节以“起点”定界（章节 end 自动等于下一章 start），MKV 保留
独立的 start/end 与多语言 TITLE 标签。

## 5. 播放器跳转与逐帧验证（`verification/`）

- `verify_player_jumps.py`：模拟播放器章节跳转（ffmpeg 输出侧精确 seek），
  对每个章节起点和每个剪辑接缝，解码实际呈现帧并与映射预期的源帧做 PSNR
  比对；同时校验成片 994 帧 PTS 完整落在帧网格上、806 个删除帧不可达。
- `verify_full_mapping.py`：用独立的 `select/aselect` 代码路径重建参考片，
  对成片全部 994 帧逐帧 SSIM 比对（最低 0.99995），避免自证。
- `verify_reimport.py`：把章节文件重新封装进无章节视频，确认 4 个章节与
  起点时间被正确读回（MP4、MKV 均通过）。
- `chapter_player.html`：浏览器播放器页面，点击章节即跳转，显示目标新时间
  与预期源帧（当前环境无 GUI 浏览器，逻辑等价的命令行验证已全部通过）。
- `jumps/`：每个跳转点的成片帧与预期源帧截图，可直接目视比对。

## 6. 一键复现

```bash
bash scripts/run_all.sh
```

依赖：`ffmpeg/ffprobe`（本环境装在 `~/bin`，静态构建含 libass）。
